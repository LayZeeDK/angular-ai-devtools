# Retired suites — the ten that could not pass

Ten of the thirty-two suites under `tests/held-out/` failed in every fresh checkout at M024 start
(`MEASUREMENT.md`). Six read a review-round record under `.project/`, a hand-written artifact that git never
tracked; four drove one browser instance and one on-device model. Each suite's claim is real, so deleting a
file without its claim would lose the asset the file guard (INTENT prohibition N3). This record holds the
claim, the subject it read or drove, why the suite could never pass in a fresh checkout, and what carries the
claim now.

`scripts/retired-suites.test.mjs` reads this file: it requires one row for each of the ten and no other row, a
filled cell in every column of every row, the absence of each retired file, and no file in the repository
naming a retired basename outside this record.

## Why these could not be repaired in place

The six `eN` suites had no source of truth a checkout carries: their input was a review record that a person
wrote by hand under an untracked path, so any repair would have meant tracking a hand-written file and calling
it a dependency (INTENT prohibition N1). The four panel suites need a launched browser with a downloaded model,
which is `verify-ai-browsers`' subject, not a corpus's; in `tests/held-out/` they were permanently red and
taught readers that a red suite is normal.
