## Settled

- Publishing — the package stays unpublished: `"private": true`, built and consumed in-repo, no registry publish and no release pipeline until a consumer asks (INTENT.md § Corrections 2026-11-02, a delegated ruling under the recorded grant; ROADMAP.md M021 § Open questions).
- No page-request transport — the panel-to-page direction stays absent and `PAGE_HOST` keeps answering `host-unavailable`; the companion answer rides the page's pushed record and the shipped replay, so `page-reads.ts` is not edited (evidence-codebase.md § The page announces once, cannot be asked again, and no request channel to the page exists at all; INTENT.md § Scope in).
- One global and nothing else — the package writes one own string key on `globalThis` and adds no renderer node, no prompt, no toast, no confirmation and no other global name (INTENT.md § Prohibitions N3, N7, AR-3, AR-6).
- Registry envelope untouched — no field is added to `ToolDeclaration` and `tool-registry.ts` keeps its pinned bytes; a companion tool, if one is ever wanted, is a new declaration module beside the envelope (INTENT.md § Constraints; evidence-codebase.md § The registry envelope is byte-identical since M018 and still pinned).
- Bundle baseline — `PRE_MILESTONE_INITIAL_KB` stays 535.44 kB and the package never enters the panel's build graph, so AR-1's pin is neither re-measured nor re-cut here (INTENT.md § Constraints AR-1; evidence-codebase.md § The bundle pin is now a ceiling with headroom).
- Read-only symbols — a vetted symbol is a lookup token, never app content and never written back, so no code generation is in scope (INTENT.md § Prohibitions N4).
- The page's record is the only source of truth — the panel infers nothing from absence and keeps its existing named states; the companion answer is one more named state, not a new inference path (evidence-codebase.md § Apparent intent; evidence-pitfalls.md § An unconditional companion key turns silence into a claim).

## Decisions

### 1. Package shape and dependency direction

- **Decision**: One new project root `packages/ai-devtools-companion/`, holding its own `project.json`, its own `package.json` (`"private": true`, `"type": "module"`, and `peerDependencies` only: `@angular/core`, `@angular/router`, `@angular/platform-browser`), a `src/index.ts` that exports `provideAiDevTools()`, a `tsconfig.json`, and a tsc-style build target writing its own `dist`. An app consumes it as an installed dependency, not as a linked source tree: the fixture takes it as a `file:` dependency that npm installs as a copy under the fixture's own `node_modules`, so the package's `@angular/*` imports resolve to the fixture's 22.2.2 and never to the root's 22.1.8. Its type check joins `npm run check` as a deliberately re-pinned fifth stage, and the root `tsconfig.json` keeps its three include entries. It may import its own modules and the `@angular/*` peers and nothing else: nothing from `apps/`, `extension/`, `scripts/` or `tests/`, and never `page-reads.ts`.
- **Runner-up**: Turn the root into an npm workspace (`"workspaces": ["apps/*", "packages/*"]`) around a `libs/`-style library, so both trees share one install. Loses twice over. There is no workspace tooling to extend — the root is one `private` package with no `.npmrc`, no `publishConfig`, no release target, and a lock whose package name already disagrees with `package.json` — and a workspace symlink makes the package resolve `@angular/*` from its real path, which is the root's 22.1.8: the second-copy failure that reduces the identity lookup to a silent "declared, no symbols".
- **Evidence**: evidence-codebase.md § There is no machinery for a second, publishable package; § The check chain and the root tsconfig are pinned to exact contents, so a new package's type-check needs an authorised re-pin; evidence-pitfalls.md § The fixture is a third build graph, not the extension build and not the panel build; § S16's identity match carries over only if the package resolves `@angular/*` to the app's own module instance; evidence-facade.md § The fixture has nowhere to swap in a development-only `ApplicationConfig`, and it carries its own Angular copy; INTENT.md § Constraints.
- **Confidence**: high — with one wave-1 check, because no project has ever sat outside `apps/`: `npx nx show projects` must list the new project.

### 2. The table entry

- **Decision**: Exactly one `globalThis` name, `ngAiDevTools`, written by a single module-level statement in the package: `globalThis.ngAiDevTools = facade`, where `facade` is a plain object of shape `{ version, '@angular/platform-browser': { Meta }, '@angular/router': { Router } }` — a version string plus one record per Angular package, each mapping a vetted symbol name to the class the package imported. The write happens in the dev-only provider the app installs, `provideAiDevTools()`, guarded by `isDevMode()`: never at module scope, never through `forwardRef`, and first-write-wins, so a second install returns the existing entry unchanged and neither throws nor replaces the object. Because a key-count snapshot cannot tell a replacement from a no-op and a `Symbol.for` write is not an own string key at all, the SC3 test snapshots the own string key names before and after the install, asserts the difference is exactly `ngAiDevTools`, asserts the own symbol keys are unchanged, and asserts `Object.is` identity of the entry across a second install.
- **Runner-up**: A `Symbol.for('ngAiDevTools')` key, or a second spelling such as `__ngAiDevTools__`. Loses because a symbol key is invisible to the own-string-key snapshot E4 names while still being a global write, and a second string name is what N3 forbids outright; the documented name is also the one the design's own detection step reads.
- **Evidence**: evidence-pitfalls.md § N3's two cheapest violations are invisible to a string-key snapshot; § Presence-only detection is the existing idiom, and its boolean cannot be told apart from a validated one; evidence-facade.md § A facade presents a lookup S16 never exercised — one global read plus an identity comparison; § Two builder settings decide whether a facade write survives at all; INTENT.md § Prohibitions N3, § Edge coverage E4, E5, E6.
- **Confidence**: high

### 3. Detection and validation

- **Decision**: Detection and validation run in the page realm, inside `extension/agent-main.js`, and reach the panel only inside the pushed state record. The probe reads `globalThis.ngAiDevTools` in the MAIN world and then validates it against the package's own facade shape before believing anything: the value is a non-null object, `version` is a non-empty string equal to a version the panel's closed table names, every package group is an object, and every symbol name is on the vetted table with a function as its value. That replaces the boolean with four named answers — `absent`, `foreign-entry` (a key that fails the shape: a stub or a stale copy), `version-unsupported` (right shape, unfamiliar version) and `declared` with the accepted symbols. Identity is compared page-side with the walk that already ships, `ɵgetInjectorResolutionPath` plus `ɵgetInjectorProviders`, feature-detected as `agent-main.js:454-471` does today, comparing each provider record with the entry's class by identity (`record.token === Router`, with `Router` read from the entry); and the record carries declared and resolved counts separately, so a second Angular copy reads "N declared, 0 resolved" rather than an empty list.
- **Runner-up**: A boolean bit set from `typeof globalThis.ngAiDevTools === 'object'`, published inside the existing `features` map. Loses on N1 and N2 at once: the chip and `app_facts` cannot tell a validated entry from a page that wrote a key, and `tool-groups` reads any `features` name with no allowlist, so the bit would become page inspection wearing the package's label.
- **Evidence**: evidence-pitfalls.md § Validation has to happen in the page realm; a panel-side read of the entry reads the panel's own global; § Presence-only detection is the existing idiom, and its boolean cannot be told apart from a validated one; § S16's identity match carries over only if the package resolves `@angular/*` to the app's own module instance; § N2's fallback is one line away; evidence-facade.md § The realm half is measured — a MAIN-world content script reads a page-written global; § The lookup half of S16 is already production code in the extension; INTENT.md § Prohibitions N1, N2, N4.
- **Confidence**: medium — the realm half is measured and the walk ships, but the facade's own read and identity comparison were never measured (evidence-facade.md § Assigned questions — answers), so the browser probe is a wave-1 blocker.

### 4. What the panel receives, and the silence rule

- **Decision**: The companion answer is a new top-level field on the `angular-ai:state` record, `companion: { state, version, declared, resolved, symbols }` — not a ninth `features` name. `buildPanelContext` writes it into the facts only after the state has been received, never before its early return, and it becomes one required member on `PanelSignals` and `PanelContext`, with the two plain-JavaScript held-out fixtures that build a context literal updated in the same task. Until the record arrives the panel shows the shipped awaiting-page state: a missing entry is never rendered as silence, and silence is never rendered as a missing entry.
- **Runner-up**: A ninth name inside the `APP_FACT_FEATURES` map. Loses because `app_facts` truncates that map to its closed eight-name tuple and the chip renders only those eight names, so the bit would reach the group gate and neither of the other two readers; and one record would then carry page inspection and the package bit with nothing distinguishing them, which is the N2 defect.
- **Evidence**: evidence-pitfalls.md § An unconditional companion key turns silence into a claim; § The panel's page-state types are closed, and two construction sites are plain JavaScript nothing checks; § N2's fallback is one line away, because page inspection already lives in the map the gates read; evidence-codebase.md § A new key on the state payload survives the wire and dies at the panel's typed reader; § `features` is the one extensible facts key, and it is read at three different fidelities; INTENT.md § Edge coverage E2, E3.
- **Confidence**: high

### 5. The refusal

- **Decision**: When the page has spoken and carries no entry, the panel refuses in one sentence that names the missing thing: "This page carries no companion package: no `ngAiDevTools` entry was found on the page's global object." It never reads as "no data yet", never as an empty symbol list, and never as a package surface assembled from page inspection: the extra-surface view renders only what the record's `companion` field carries, while the fingerprint chip keeps rendering the eight page-published bits beside it on its own surface. Each non-detected case keeps its own sentence — `foreign-entry` says the key is not the package's shape, `version-unsupported` names both versions — and `declared` with zero resolved symbols is not a refusal but the honest "declared, no symbols" state, reported with its declared and resolved counts.
- **Runner-up**: One generic "the extra surface is unavailable" line, or a fallback that fills the view from `facts.features`. Loses because a single line makes a stub, an old version and a missing package indistinguishable, and the fallback is exactly the difference this milestone ships (N2): the user would be shown page inspection labelled as the package's surface.
- **Evidence**: evidence-pitfalls.md § N2's fallback is one line away, because page inspection already lives in the map the gates read; § An unconditional companion key turns silence into a claim; § S16's identity match carries over only if the package resolves `@angular/*` to the app's own module instance (the "declared, no symbols" failure is silent); evidence-codebase.md § Apparent intent — five named states exist so silence never renders as absence; INTENT.md § Success criteria SC2, § Prohibitions N1, N2, § Edge coverage E1, E2, E3.
- **Confidence**: high

### 6. The tree-shaking proof

- **Decision**: SC4 is proven on the fixture's development build and nothing else. The command is `ng build --configuration development` in `spikes/ng222-app`, with an output path outside the fixture's tracked tree; the emitted unminified browser bundle must contain the entry name `ngAiDevTools` and the vetted class the entry carries, and that same output must then be served so the panel detects the entry and names a symbol. A search of the bundle alone is not the proof, and a served page alone does not show the write survived. The proof is never taken on `build`, whose `defaultConfiguration` is `production`, and never on `build-extension`, which sets no configuration and therefore runs optimized; `buildOptimizer` is not an option of `@angular/build:application` at all, so N5 is satisfied by naming the development configuration rather than by avoiding a flag that no longer exists.
- **Runner-up**: Prove it on `ng serve`, or on the panel's own `build-extension`. Loses because `build-extension` compiles the panel and never the package, so nothing it emits can carry the facade, and a production build answers a different question: the entry is absent there by design, so the honest "no entry" refusal would read as a passing result.
- **Evidence**: evidence-pitfalls.md § This builder has one tree-shaking lever (`optimization`), and both extension-side targets run optimized; § The fixture's default build is production, and the design's dev-mode guard makes that mistake look like a clean refusal; § The fixture is a third build graph, not the extension build and not the panel build; evidence-facade.md § `buildOptimizer` does not exist in the fixture's builder, and the fixture's default build is production; § The fixture's development configuration still bundles, and the builder never disables tree shaking; § Unverified — the command and the expected observation; INTENT.md § Prohibitions N5.
- **Confidence**: medium — the configuration facts are high, the observation is unmeasured because no build was run, so the measurement itself is wave 1.

### 7. The re-announce path

- **Decision**: `agent-main.js` gains a bounded companion re-check that re-emits the same `angular-ai:state` payload when the companion answer changes from `absent`, then stops. No new event type, no new message type, and no panel-to-page request: the relay's existing latch then holds the newest payload and answers the shipped replay, so a panel opened after the page's one-shot record still sees the entry. The re-check is finite — a handful of attempts on a timer, cleared on the first non-absent answer or on the last attempt — and the panel keeps showing awaiting-page until a state arrives, so the refusal can never fire before the re-check has run. The package itself stays dumb: it writes one key and knows nothing about the extension.
- **Runner-up**: Require the package to write its entry before `document_idle`, or let the package dispatch a page event the extension listens for. Loses both ways: a package cannot promise when an app's bootstrap runs, and a package-side event makes app-visible code depend on the extension's private vocabulary — a second contract inside someone else's build, which is exactly the blast radius this milestone keeps at one key. A third candidate, a real `PAGE_HOST` transport so the panel can ask, is out of scope by INTENT.md § Scope in and unbuilt at this head.
- **Evidence**: evidence-pitfalls.md § The only detection surface is a one-shot pushed record; there is no ask; § An entry written after bootstrap is invisible, because nothing re-announces; evidence-codebase.md § The page announces once, cannot be asked again, and no request channel to the page exists at all; § Architecture — the relay latch, one replay request, and background tab routing; INTENT.md § Success criteria SC1, § Scope out.
- **Confidence**: high

### 8. The vetted table and its version key

- **Decision**: The table is executable code in the package, not generated data: one module exports the vetted map and its `version` string, imports the classes from the `@angular/*` peers so the values are real class identities, and the panel holds its own closed copy of the accepted names and versions. This milestone vets two symbols — `Router` from `@angular/router` and `Meta` from `@angular/platform-browser` — and no more. The table is versioned by the package's own `version` string, with the Angular version it was vetted against recorded beside it, and 22.2.2 is that version because it is the copy the identity comparison actually meets in the fixture.
- **Runner-up**: A generated JSON digest following `extension/error-digest.json` — a build target writes a data file with one free-text version and the panel imports it. Loses because a data file can only carry names, and the facade's whole contribution to the lookup is a class object compared by identity; a name table reduces the panel to exactly the Tier-1 token-name matching S16 recorded as degraded.
- **Evidence**: evidence-codebase.md § The nearest precedents for a vetted table are two incompatible hand-rolled shapes; § Version negotiation exists in four places, with three different answers for a version it cannot read; evidence-facade.md § A facade presents a lookup S16 never exercised — one global read plus an identity comparison; § The fixture has nowhere to swap in a development-only `ApplicationConfig`, and it carries its own Angular copy; evidence-pitfalls.md § S16's identity match carries over only if the package resolves `@angular/*` to the app's own module instance; INTENT.md § Prohibitions N4.
- **Confidence**: medium — the shape follows the design, but which Angular version the table certifies is a promise fixed here rather than a measurement, and only 22.2.2 is measured.

### 9. The docs-audit repair

- **Decision**: This milestone owns the regenerated audit's repair as exactly one task, landed before any SC5 evidence is claimed. The task returns the two pins to green at this head: `docs/autonomy-gaps.md` is added to the audit's `## Descriptive docs` list because `scripts/autonomy-gaps.test.mjs` requires it there, the sixteen `fix-doc` and three `accept-drift` rulings already recorded in the audit's `## User rulings` are applied or carried exactly as ruled, and `scripts/docs-audit-disposition.test.mjs` and `scripts/autonomy-gaps.test.mjs` are the task's Verify. It is a wave-1 task, because `npm test` is red at the base until it lands and SC5 cannot be observed before it.

Loses because both pins fail at the same head and the descriptive list is one line of the same repair; splitting them across waves buys a second red gate in between.
- **Evidence**: INTENT.md § Constraints (the audit regenerated at this head makes the disposition pins fail, and `scripts/autonomy-gaps.test.mjs` requires the descriptive listing); .project/research/DOCS-AUDIT.md § Summary, § Descriptive docs, § User rulings; .project/LESSONS.md § 019-context-and-jobs (a milestone that re-inspects documents must own the DOCS-AUDIT remediation in its plan); .project/STATE.md § Log, M019's plan repair for the same cause.
- **Confidence**: high

## For the planner

- **Wave-1 blockers**: Five assumptions to burn down before any surface work, in this order.
  1. The docs-audit repair, because `npm test` is red at the base until the descriptive listing and the disposition pins are green, so a later green would mean nothing.
  2. The facade read and the identity comparison: serve the fixture's development build and evaluate in the page's main world `ng.ɵgetRouterInstance() === ng.getInjector(document.querySelector('app-root')).get(globalThis.ngAiDevTools['@angular/router'].Router)`, which must be `true`; a `false` or a throw means two Angular copies and the detection story is unproven.
  3. The development-build observation: `ng build --configuration development` must keep the `ngAiDevTools` write and the class in the emitted bundle, and `isDevMode()` must be true in that configuration at this head.
  4. The E4 baseline: snapshot the fixture page's own `globalThis` string keys at `document_idle` before the package exists, so "exactly one key" is measured against an observed set rather than an assumed one.
  5. The bundle headroom: the head's panel initial total is unmeasured because no build output exists in the checkout, so measure before any byte is budgeted, and keep the package out of the panel's graph entirely.
- **Walking skeleton**: One thin end-to-end slice, with no polish: the package at `packages/ai-devtools-companion/` exporting `provideAiDevTools()`, which writes `globalThis.ngAiDevTools` under `isDevMode()`; the fixture's development build installing it through a dev-only provider file plus one `fileReplacements` entry; `agent-main.js` reading and validating the entry and publishing `companion` in its state record; the relay's existing latch and replay delivering that record to a panel opened afterwards; the panel refusing by name on a page without the entry and naming the package's declared symbols on a page with it. No new route, no new event, and no package byte in the panel's eager graph.
- **Pitfalls → tasks**: Every known trap, with the task that must dodge it.
  - A one-shot record with no ask → the re-announce task adds the bounded re-check and reuses `angular-ai:state`; anything shaped as a request fails silently.
  - An entry written after bootstrap → the same task, whose Verify opens the panel after the page has loaded rather than during it.
  - Presence-only detection → the validation task owns the four named answers and the facade shape, and no `typeof` boolean survives.
  - A panel-realm read → the probe lives in `agent-main.js`, and its test stubs the page realm, never the panel's global.
  - N2's fallback → the surface task reads only the record's `companion` field, never `facts.features` and never the eight `app_facts` rows.
  - Silence rendered as absence → the adapter task adds the key after the state arrives, and a test asserts the empty facts object stays empty.
  - A closed `PanelSignals` → the type task updates the two plain-JavaScript held-out fixtures in the same file list, and no `?? 'absent'` default is allowed.
  - `forwardRef` purity → the write is a property assignment inside a provider call, never a `forwardRef`-built table.
  - `buildOptimizer` → the proof task spells `--configuration development` and never writes a bare `ng build`.
  - A key-count snapshot → the SC3 task asserts the own-key set difference plus `Object.is` identity across a second install.
  - Two Angular copies → the identity task reports declared and resolved counts separately, so a wiring defect is visible rather than honest-looking.
  - `docs/autonomy-gaps.md` descriptive → the audit task owns it in wave 1, before any SC5 claim.
  - The relay's existing page marker → browser verification must not read that marker as the package's effect.
