## Decisions

### Decision 1 — Helper-pin placement and the installed-suite probe budget

- **Decision**: Extend the existing suite in place and give the four new pins a zero-full-suite budget. Concretely: one new exported `HELPER_PINS` table in `scripts/user-scope-autonomy.mjs` shaped like `RULES` (id, name, absolute helper path, the tokens each pin asserts, and the one command that probes it), a `checkHelpers()` entry point that `check()` calls after the RULES loop, and four new `test()` cases in `scripts/user-scope-autonomy.test.mjs` that drive that table the way the E1/E4/E5 cases already drive `check()`. Every new pin probes one helper directly — `node --experimental-strip-types gsd.ts <subcommand>` under the resolved `gsdDir`, or `python -B check_handoffs.py plan` — never `runGsdTests()`. The suite's existing `health: the real installed helper suite exits 0` case stays the single full-suite spawn; the copied-suite case in E2 stays as it is, because removing it would weaken a check (`N3`). Worst-case added wall time is three helper spawns of roughly 1-2 s each.
- **Runner-up**: A second suite, `scripts/helper-pins.test.mjs`, importing the same module, with one full installed-suite spawn per pin so each pin would get the whole 273-test suite as its oracle. It loses on three counts that the running suite makes concrete: `runGsdTests()` already costs ~53 s per spawn (`INTENT.md` `## Constraints`; `.project/research/evidence-codebase.md` § Map), the suite as shipped already spawns it twice (the health case and E2's copied-suite case), so per-pin spawns would put one `npm test` into the minutes the INTENT's Risks warn about; and a full-suite spawn tells the operator which helper regressed only through 273 test names, whereas a direct probe names the file and the rule id (`E1`, `N1`).
- **Evidence**: `.project/research/evidence-codebase.md` § Finding: `npm test` is not hermetic — it runs test files out of the user home directory; `scripts/user-scope-autonomy.mjs` (`runGsdTests` 240 s timeout at the `runGsdTests` definition, `HELPER_TOKENS`, `check()`), `scripts/user-scope-autonomy.test.mjs` (the `health:` and `E2:` cases, `RULES`, `check()`); `INTENT.md` `## Risks` (the three-pin timing risk) and `## Corrections` (extend, do not add a suite).

### Decision 2 — How each of the four helper defects is proven, per defect

- **Decision**: A mix per defect, chosen so each pin fails on its own regression and none of them asserts output wording:
  - `brief-check` paid-type effort ladder — **mix**. Static: assert `lib/brief-check.ts` contains both paid tokens `paid-deepseek-v4-1-flash` and `paid-glm-5-3-flash` inside the effort-ladder alternation, naming the absolute file. Behavioural: one `gsd brief-check --task-file <fixture task> --brief <fixture brief> --json` run, asserted on the `warnings` array — a brief that carries a paid route must produce no `missing effort ladder mention` warning, and a brief that carries no route token must produce it. This fails when the paid tokens are dropped from the alternation (`lib/brief-check.ts:62`), which is the exact regression; `status` is not asserted because a warning never blocks (`lib/brief-check.ts`, `checkBrief`).
  - `plan-lint` `path::test_name` Held-out form — **behavioural, with a static anchor**. Behavioural: `gsd plan-lint --repo <fixture> --json` over a fixture `.project/plan/PLAN.md` whose `## Held-out checks` table gives the Test cell as `scripts/fixture-pin.test.mjs::a named case` and whose task file declares `scripts/fixture-pin.test.mjs` and runs it in `## Verify`; assert `ok: true` and no finding whose `check` is `held-out-test` or `held-out-verify`. Static anchor: the split on `::` before the files comparison (`lib/plan-lint.ts:551`), so a failure names the file. Removing the split turns the `::` cell into a non-matching path and the behavioural half goes red.
  - `check_handoffs` Intent-coverage row parsing — **behavioural**. Two runs of the public subcommand, `python -B check_handoffs.py plan --repo <fixture>`: a fixture whose `## Intent coverage` gives one acceptance id per row must exit 0 and list the owned criteria; a fixture with a three-cell row carrying several ids in the acceptance cell (for example `SC1 | T001 | AC1, AC2`) must exit non-zero and print `Intent coverage row is unreadable`. The regression being pinned is the silent skip at `_coverage_rows` (`check_handoffs.py`, the `continue` branch before the `no rows` error) — a skipped row loses a criterion and the plan can then pass with the criterion unowned. Assert the exit code and that substring, never the surrounding sentence. The fixture needs `.project/STATE.md` at `plan/active`, a one-criterion `INTENT.md`, one wave in `PLAN.md` and one task file; if that fixture proves to need more of the plan contract than the regression does, the probe drops to a module-level call of `_coverage_rows` over the two fixture strings — same assertions, same failure condition.
  - serial retry that leaves a rejected attempt unparkable — **static token pin plus one behavioural contract probe**, because the installed copy exposes no pure seam: the resume decision (`isolation.py`, the `resume`/`landing_retry` block) is git- and worktree-coupled, so a behavioural reproduction would need a temp repository, a sidecar worktree and a driver run — minutes, not seconds. Static: assert the installed copy still carries (a) the serial branch of `isolate_live` (`dispatch_driver.py`, the `mode == "serial"` and `task_branch == "null"` guards that keep a blocked serial attempt reportable) and (b) the metadata-clearing reset that lets a rejected serial attempt return to `pending` without retaining `agent`, `base`, `worktree` or `task_branch`. Behavioural: `python -B build_state.py ready --repo <fixture>` over a temp git repository with two task files — a parked serial task (status `pending`, the four dispatch fields `null`) must be ready, and a pending task that still retains `worktree` must exit non-zero naming `pending task retains dispatch metadata` (`build_state.py`, `_validate_ready_metadata`). That pair pins the contract the retry depends on; the static half is what fails on a reversion of the fix itself. Residual risk, recorded: a subtle logic change that keeps the tokens leaves the static half green.
- **Runner-up**: Static-only pins on all four — cheapest, no fixtures, and enough for `brief-check`. It loses because a token pin cannot see the parser behaviours that actually regressed: the `::` split, the silent skip in the coverage parser, and the reset contract are all reachable in seconds through the public subcommands, and a pin that cannot fail when the behaviour regresses is not a pin. The reverse — behavioural runs of the full installed suite for all four — loses on the 53 s spawn (`INTENT.md` `## Risks`).

### Decision 5 — Shape of the owner-directed analysis document

- **Decision**: `docs/autonomy-gaps.md`, in the repository, written from this run's own record. Shape: a short scope note naming the milestone and stating that the analysis covers only the gaps this milestone actually met, that the user-scope edits live outside the checkout and are cited by absolute path, and that this repository contains the pin, not the fix. Then one `## Gap — <name>` section per gap, each with five fixed fields:
  - `Met:` what stopped the run, at which point, quoting the helper's own output or the absolute path it named.
  - `User-scope change:` the absolute file under `~/.commandcode` that changed, the behaviour before and after, and the explicit statement that the edit was made outside this checkout.
  - `Pin:` the repository assertion that fails without the change, named by file, rule id and test name.
  - `Verified:` the command actually executed with its exit status and output, or the literal `not-run` and why — a run that did not happen may not be described as one that did.
  - `Remaining:` what still needs a human and what a later milestone would have to build to remove them.
  Closing section `## What this document does not prove`: no run is claimed that did not happen; no static half of a pin is presented as a behavioural verification; no user-scope change is claimed to be in this repository's history; no model name, work address or domain appears anywhere in it.
- **Runner-up**: A section inside `AGENTS.md`, or a note under `.project/`. Both lose: INTENT names the path, the audience is the next milestone's orchestrator rather than this checkout's agent rules, and `check_docs_audit.py`'s inventory derivation excludes everything under `.project/` unless alignment mode is on, so a `.project/` location would sit outside every gate — the same escape from verification the document exists to describe.
- **Evidence**: `INTENT.md` `Scope: in` last bullet, `## Corrections` first and second bullets, `## Risks` (a wrong user-scope fix reads like a bad test); `check_docs_audit.py` `derive_inventory` (the `.project/` exclusion); `scripts/user-scope-autonomy.mjs` (the shape a pin citation must match: rule id, absolute file, reason).
