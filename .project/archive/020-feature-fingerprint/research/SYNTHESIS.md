# Synthesis

## Settled

- Envelope immutability — `apps/angular-ai-devtools/src/app/tool-registry/tool-registry.ts` keeps its bytes and its SHA-256 pin: no `group` field, no grouped wrapper type, and the pin is not re-cut (INTENT.md § Scope out, § Corrections 2026-11-02; `scripts/registry-envelope-pin.test.mjs`).
- Grouping is a read-only projection — membership and gates are declared beside the envelope and read `registry.tools()`; nothing is fed back through `provideTools` or `declare` (INTENT.md § Corrections 2026-11-02; evidence-pitfalls.md § Grouping must be a read-only projection; re-declaring throws).
- Chip content — the chip names exactly the eight page-published `APP_FACT_FEATURES` bits and nothing else; DI-graph, stale-view and error-digest capabilities have no published bit and do not appear (INTENT.md § Corrections 2026-11-02; Prohibition N1).
- Version source — a group gate and the chip read the `[ng-version]` root enumeration, with `app_facts` authoritative when the two disagree; the existing 22.1.3 hard block keeps its own meaning (INTENT.md § Corrections 2026-11-02; Prohibition N2).
- Chat surface — the group list belongs to a new chat entry point in the panel, because the registry has no production consumer at this head (INTENT.md § Corrections 2026-11-02).
- Budget policy — the operative constraint is "must not make the initial bundle worse" than the recorded 535,440 B, and the constant is never raised to reach green (INTENT.md § Corrections, Prohibition N5; `scripts/panel-bundle-budget.test.mjs`).
- Page-realm purity — no DOM is added to the inspected page, so every state path is a message or an event, never an injected element (INTENT.md § Prohibitions N6, AR-3; evidence-codebase.md § The content-script relay injects a visible badge into every inspected page — the only tool-owned DOM stays relay's existing marker).
- Cannot-tell is its own state — the silence state is distinct from the non-Angular refusal and from `notSupported()` (INTENT.md § Corrections 2026-11-02, Prohibition N4; evidence-pitfalls.md § A silent page already renders as a measured empty state).

## Decisions

### State delivery to the panel

- **Decision**: Last-known-state replay from the relay, pulled by one panel request. `extension/relay.js` latches the last `angular-ai:state` payload it forwarded (the same latch pattern it already uses for `angularDetected`), listens for one request on `chrome.runtime.onMessage` and re-sends the latch; `extension/background.js` routes the panel's request to the inspected tab by `tabId` and returns the reply; `apps/angular-ai-devtools/src/app/extension-message.service.ts` sends exactly one request when constructed and writes the reply through the existing `features`, `zoneMode` and `stateReceived` signals. The same latch and the same request also carry the `[ng-version]` string, so one round trip recovers state and version together; the new adapter in `apps/angular-ai-devtools/src/app/panel-context.ts` builds `ToolContext.facts` from those signals before any `registry.execute` call. No new permission, no storage, no page-side handler.
- **Runner-up**: A last-known-state cache in `extension/background.js` backed by `chrome.storage.session`. Loses because an MV3 service worker is evicted between the page load that produced the state and the panel open that needs it, which is the exact interval the cache exists to cover, and it needs an async read plus a tab map the relay latch gets for free. The third candidate, a new page-side responder in `extension/agent-main.js` that recomputes `featuresOf` on request, loses for a stronger reason: `agent-main.js` announces nothing at all without `window.ng`, so the responder would be dead on exactly the production page the panel most needs an answer from.
- **Evidence**: evidence-pitfalls.md § There is no replay, so a panel opened after page load never sees the state it needs; § The panel has no page DOM; the only `[ng-version]` read is in the relay, and the version is logged rather than signalled; evidence-fingerprint.md § where the `[ng-version]` root enumeration exists today, and what it yields per fixture.
- **Confidence**: medium

### Version for a group gate

- **Decision**: The version reaches the panel on that same latch and request. `extension/relay.js` caches the `angular-detected` version it already reads at page load, `extension/background.js` replays it, and `ExtensionMessageService` gains `appVersion: Signal<string | null>` beside `features`, `zoneMode` and `stateReceived`; it already receives the message and currently writes the value only into the cause log. The adapter copies it into the group-gate context as `version`, and `AppFactsSnapshot` is deliberately not extended: `app_facts` renders the snapshot, and a version field there would put a fact on the tool result that the `angular-ai:state` payload never carried. The chip and the gate both read the one context object `{facts, version, stateReceived}`.
- **Runner-up**: Add `version` to the `angular-ai:state` payload and have `extension/agent-main.js` read its own `[ng-version]`. Loses because that payload does not exist on a production Angular page at all, so the version would be missing in the one class where the version is the only fact available; it also changes a payload shape that both the page tests and the panel read.
- **Evidence**: evidence-fingerprint.md § `[ng-version]` survives a production build while `window.ng` does not, so "production Angular" is a nameable state with a version and no facts; § where the `[ng-version]` root enumeration exists today, and what it yields per fixture; evidence-pitfalls.md § The panel has no page DOM; the only `[ng-version]` read is in the relay, and the version is logged rather than signalled. This finding also overrules evidence-codebase.md § Version gating exists twice, in two languages, with incompatible semantics, and never reaches the panel on its "incompatible semantics" wording: the pitfalls finding reads both functions and shows the unknown case agrees.
- **Confidence**: high

### Group projection shape beside the pinned envelope

- **Decision**: One new pure module `apps/angular-ai-devtools/src/app/tool-registry/tool-groups.ts` holding a static `TOOL_GROUPS` table and one function `projectToolGroups(tools, context)`. Each entry is `{id, title, memberIds, minVersion, requiredFeature?}`, where `memberIds` is a list of tool ids and `requiredFeature` is one `APP_FACT_FEATURES` name; membership is by id, never a field on the declaration. `context` is `{facts, version, stateReceived}`. A group is returned only when at least one member exists with `publish === 'model'`, the version parses and is at or above `minVersion`, and, when facts are present, `supported === true` and `requiredFeature` is true (facts win over the version, N2). Every excluded group is absent from the returned list and recorded in a returned `excluded` array as `{groupId, reason}` with a named reason, so the entry point can state why the list is empty without an empty group ever appearing. An unparseable or missing version excludes with the cannot-tell reason rather than opening a group; `requiredFeature` is redundant with `supported` on the fixtures at this head (all eight bits flip together) and exists so an injected or later partial payload can gate a group and so N2 has a concrete meaning.
- **Runner-up**: A `group` field, or a grouped wrapper around `ToolDeclaration`, inside `tool-registry.ts`. Loses twice: it re-cuts a SHA-256-pinned file whose immutability is an acceptance criterion, and re-declaring a decorated declaration throws `ToolDeclarationError` at injector construction rather than at render.
- **Evidence**: evidence-pitfalls.md § Grouping must be a read-only projection; re-declaring throws; § `publish` is the filter nobody applies, and one shipped tool is panel-only; § The two version gates agree on the unknown case; the premise that they disagree is wrong; evidence-codebase.md § There is no tool-group concept, only per-tool axes; § The registry envelope is SHA-256 pinned, so "add a tool" and "extend a tool declaration" have different costs; evidence-fingerprint.md § 22.1.8 and 22.2.2 publish identical key sets, so no supported version yields a partial fingerprint.
- **Confidence**: high

### Three page classes and their panel states

- **Decision**: One pure classifier `pageState(context)` yields exactly three kinds, rendered by the chat entry point. (1) `no-angular-root`: no version and no state, rendered as a named refusal whose text names the evidence, "No Angular root found on this page", rather than concluding "not an Angular app", because a root created through `ViewContainerRef.createComponent` also carries no `ng-version`. (2) `cannot-tell`: a version is known but no state arrived (production build, `ngDevMode` off, or a page that never announced); the text names the version and says the debug surface is absent, and no feature and no group is shown. (3) `fingerprint`: state received; the chip lists all eight `APP_FACT_FEATURES` in declaration order, each present or absent by name, and when `supported === false` it renders the page's own `reason` verbatim and makes no zone claim, because `zoneMode` reads `noop` on the Zone rejection path; `zoneMode` is displayed only when `supported === true`. The classifier reads `stateReceived()`, never `notSupported()`, and the six explainers keep their current behaviour. This inverts the INTENT risk that the version can be absent on a production build: the version is the part that survives, and the debug global is the part that does not.
- **Runner-up**: Reuse `notSupported()` and `notSupportedReason()` and add a fourth state in the explainers' existing pattern. Loses because both default to "not negative", so silence and zero already look identical — the exact trap N4 forbids — and editing the six explainers is outside this milestone.
- **Evidence**: evidence-fingerprint.md § `[ng-version]` survives a production build while `window.ng` does not, so "production Angular" is a nameable state with a version and no facts; evidence-pitfalls.md § `[ng-version]` is not dev-mode; a production page has a version while its features are unreadable; § `zoneMode` in the payload is `noop` on the Zone.js rejection path; § A silent page already renders as a measured empty state; § `readFeatureBits` collapses "no map" and "no usable bits" into different values, and `{}` is the dangerous one.
- **Confidence**: high

### Chip and group list placement, and the bundle boundary

- **Decision**: Both live in one new surface, a lazy route `chat` registered in `apps/angular-ai-devtools/src/app/app.routes.ts` with `loadComponent`, whose component `apps/angular-ai-devtools/src/app/chat-entry.component.ts` renders the chip above the group list. No shell component is added to `app.ts`, which is only a router outlet, and no chip appears on the six explainer routes, because the intent puts the chip in the chat the groups belong to. The byte-exact budget is met by keeping the route lazy, so its component and the three pure modules land in a chunk `index.html` never references, and by converting at least one existing eager explainer route to `loadComponent` in the same task, so the single new eager route entry is more than offset. The constant in `scripts/panel-bundle-budget.test.mjs` is never touched, and acceptance is that the test prints at most 535,440 B.
- **Runner-up**: An eager chip in a shell header around the router outlet, so it shows on every route. Loses on two counts: every byte it adds is eager and must be offset from somewhere, and it would put a feature claim, or a cannot-tell line, on all six explainers and change the empty-state behaviour the milestone must not break.
- **Evidence**: evidence-pitfalls.md § The bundle pin has zero margin, and only eager files count; evidence-codebase.md § The panel is over its own 520 kB budget and the overshoot is pinned byte-exactly; § There is no context chip and no panel surface that could stand in for one; INTENT.md SC4, Prohibition N5.
- **Confidence**: medium

### Partial-fingerprint test strategy

- **Decision**: A new held-out `node:test` suite under `tests/held-out/` imports the pure modules directly with `--experimental-strip-types` and injects the payload, because no fixture and no supported version can produce a partial map. It builds a plain map from the eight `APP_FACT_FEATURES` names with exactly two true, calls the adapter and the chip model, and asserts: eight entries in `APP_FACT_FEATURES` declaration order; exactly the two injected names present and the other six absent by name, so deleting an absent entry fails (E1); two identical calls produce byte-identical chip text (E2); an all-false map produces eight absent names, not an empty chip and not an invented one (E3); and `null`, an empty object and any partial map produce the cannot-tell state, never absences. The same injected context drives the gate cases: a version exactly at a group's `minVersion` includes the group, the same version one patch below excludes it and the group is absent from the list (E4), and when every gate fails the projection returns zero groups plus the named empty reason (E5). The service-to-signal wiring stays in the Angular spec, which follows the `extension-message.service.spec.ts` pattern.
- **Runner-up**: A production-build fixture, or a fixture served with the debug global disabled, to obtain a real partial map. Loses because a production build yields eight false rather than two of eight, the key set is identical at 22.1.8 and 22.2.2 so no version changes it, and adding a fixture route needs an owner ruling under AGENTS.md. The real writer cannot produce a partial map at all: `featuresOf` always writes all eight keys.
- **Evidence**: evidence-fingerprint.md § both fixtures are dev builds of the same Angular 22.2.2, so all eight bits are true on both and none distinguishes them; § `featuresOf` always writes all eight keys, so the panel's "unpublished bit" branch is unreachable from this writer; § Dead ends (E1 and E3 must be driven by injected payloads, not by a fixture state); evidence-pitfalls.md § Every one of the eight bits flips together on every fixture at this head.
- **Confidence**: high

## For the planner

- **Wave-1 blockers**: Four assumptions to burn down before surface work. (1) The replay gap in a live session: load the built extension, open DevTools after the page has loaded and assert the chip is not blank, because the finding's session consequence is medium evidence while "no replay path exists" is high. (2) The routing of the replay request: the panel must name its inspected tab to the background, and that tab identity path is unproven at this head. (3) The byte arithmetic: measure the lazy `chat` route plus one converted explainer route with `scripts/panel-bundle-budget.test.mjs` and require at most 535,440 B; if no behaviour-neutral conversion exists, stop rather than raise the constant. (4) The production Angular class: run the settling check `evidence-pitfalls.md` already names, building `spikes/ng222-app`, serving it, and reading `[ng-version]` and `typeof window.ng`.
- **Walking skeleton**: One thin end-to-end slice with no polish: the lazy `chat` route whose component injects `TOOL_REGISTRY`, builds the context from `features`, `zoneMode`, `appVersion` and `stateReceived`, renders the chip from `featureFingerprint(context)` (eight named entries, the cannot-tell line, or the named refusal) and the list from `projectToolGroups(registry.tools(), context)`, driven by a held-out test that injects a two-of-eight payload and a version one patch below a gate, with the bundle test green.
- **Pitfalls → tasks**: No replay → the state-delivery task must add the relay latch and the request, not merely read the signal. Log-only version → the same task must expose `appVersion` and route it into the gate. `zoneMode` says `noop` on the rejected-Zone path → the chip task must show the page's `reason` and suppress the zone mode when `supported` is false. The `EMPTY_FACTS` default → the entry-point task must build `ToolContext` before any `execute`, and a test must prove `app_facts` never answers `host-unavailable` from a live context. Re-declaring throws → the projection task must filter `registry.tools()` and never call `provideTools` or `declare`. `publish` unfiltered → the projection task must filter `publish === 'model'` and drop a group left with no model-visible member. The reach guard → no new file may import `page-reads.ts`, so page data must come through `TOOL_REGISTRY`. Silence renders as an empty state → the chip task must derive its third state from `stateReceived()`. `readFeatureBits` returns an empty object → the adapter task must treat `null`, an empty object and a partial map as cannot-tell. The byte-exact pin → the entry-point task must ship lazy and offset, and must not touch the constant. The two gates' unknown case → the gate task must define unknown as excluded with a named reason, never as open. Two SSR roots → read the single version string with `querySelector`, never a root count. The relay's green badge → verification must not mistake it for the chip.
