# Research — M025 `panel-verify-breadth`

## The roadmap's premise is stale

`### M025 — panel-verify-breadth` says the gap is that `npm run check` never type-checks the panel. That gap was
closed by **M018 T008**: `package.json` runs `check:panel` → `tsc -p apps/angular-ai-devtools/tsconfig.check.json`,
whose header records why (the `@angular/build` transform pipeline never reports a type error, so the config
type-checks the panel's sources plus everything they import, and deliberately refuses an allow-list — N4).

So the breadth that is genuinely missing is **`extension/`**, which is plain JavaScript and type-checked by
nothing.

## Measurement

Probe: `tsc --noEmit --allowJs --checkJs --target ES2022 --module ESNext --moduleResolution Bundler`.

| Configuration | Errors |
| --- | --- |
| `strict: true`, whole `extension/` | 7308 |
| `strict: false`, whole `extension/` | 220 |
| `strict: false`, excluding `extension/panel/**` | **33** |
| `strict: true`, excluding `extension/panel/**` | 0 measured; the strict count is dominated by implicit-any |

`extension/panel/` holds **build output** — `main.js` and `chunk-*.js`, 187 of the 220 errors between them. It is
generated by the panel build and must not be hand-edited, so a check over it measures the bundler, not the source.

## The 33 real errors

- 20 × `TS2304 Cannot find name 'chrome'` — the Chrome extension API has no ambient type in this repository.
- 6 × `TS2339 Property 'detail' does not exist on type 'Event'` — code reads `event.detail` on a plain `Event`.
- 1 × `TS2451 Cannot redeclare block-scoped variable 'status'`.
- 1 × `TS2339 Property 'textContent' does not exist on type 'string'`.
- 2 × `TS2345` on a `CustomEvent | {…}` union passed where `Event` is expected.
- 3 × others in `stale-view-worker.js`.

Two of these are genuine defects the check exists to find: reading `.detail` off an `Event` is fine at runtime
only because the listener receives a `CustomEvent`, and `status.textContent` on a string is a real confusion.

## Constraint

`strict: true` over the extension is not reachable in one milestone (7308 errors, almost all implicit-any in
hand-written JS). The check must therefore be added at `strict: false` with the strict gap recorded, rather than
pretending the sources are strict-clean.
