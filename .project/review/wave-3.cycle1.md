## Findings

- Advisory (T004, guard coverage): the reach guard resolves only relative specifiers (`./…`, `../…`); a bare or aliased specifier such as a tsconfig `paths` alias to `page-reads` would resolve to `null` and pass silently. No path alias exists in the app's tsconfigs today, so the hole is latent rather than live — worth closing when the next explainer lands, e.g. by failing on any unresolvable specifier that merely mentions `page-reads`.
- Advisory (T004, module state): `read-tools.ts` records the registering injector in a module-level `readToolsInjector`, so the last environment that ran `provideReadTools()`'s initializer wins for every subsequent call. Benign for the single-app panel and safe (it falls back to the honest `UNAVAILABLE_PAGE_HOST`), but a second concurrently bootstrapped environment in a future test would silently share one injector.
- Advisory (T004, guard parser): `stripComments` leaves string/template literals intact, so a template literal quoting `import … from './page-reads'` would be a false positive (fails safe), and the guard's own comment notes a regex literal containing `//` would be misparsed — acceptable today, documented in the file.
- Advisory (T005, subset limits, deliberate): `title`, `placeholder`, `value`, `fieldset/legend`, `figcaption` and the `img[alt=""]`→`presentation` mapping are outside the module's subset and are never consulted, and an `img[alt=""]` answers role `img` with no name rather than `presentation`. Each omission is documented in the module header and asserted in the spec, and the strictness serves N3 — but the later Aria explainer (M-scope beyond this wave) should know `title`-named controls will report "no accessible name".
- Advisory (T005, spec hygiene): the read-only case observes mutations on the fixture tree and `document.body` only; it does not observe the elements' own attribute writes after `observer.disconnect()`. Not a defect — the observed window covers all reads — just a note on what the proof covers.
