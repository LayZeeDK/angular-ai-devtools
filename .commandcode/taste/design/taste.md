# Design principles for the devtools product

- Combine browser built-in AI APIs with plain deterministic TypeScript/JavaScript: process graphs in chunks, validate, sanitize and compute in normal code (main thread or Workers) and reserve the Prompt API and friends for what code cannot do, specifically to mitigate the small 7-9K context windows. Confidence: 0.9
- The product is only a web (browser) extension and must never generate code — no migrations, no app-specific code, not even inside its own DevTools runtime. Findings may name the modern Angular pattern (and an official Angular migration schematic may be named) and explain why something is an anti-pattern, but never produce the fix. Confidence: 0.9
- Prefer public, first-party APIs (the `angular:*` discovery tools) over internal `ɵ`-prefixed symbols; internal APIs and app-side opt-ins (exporting symbols to `globalThis`, WebMCP) are last-resort, clearly labelled stretch prerequisites because they break "works with any app". Confidence: 0.8
- Any `globalThis` runtime export must be a small pre-vetted allowlist of first- and third-party packages (`@angular/*`, `@ngrx/*`), never arbitrary app services looked up by name. Confidence: 0.8
- WebMCP is supported by consuming apps that already expose it, or as an app opt-in prerequisite; the extension does not publish its own tools as WebMCP. Confidence: 0.75
- Text handed to built-in AI APIs must be sanitized: strip license and copyright notices (e.g. the Angular error digest), cap lengths, wrap page-derived strings as untrusted. Confidence: 0.75
- Companion-package naming: `provideAiDevTools()` with per-package secondary entry points such as `provideAiNgrxDevTools()`; casing matters ("Ai" + "DevTools"). Confidence: 0.75
- Avoid a fixed browser/prerequisite only where it is not needed, but a Chrome Beta or Edge Dev prerequisite is acceptable for the AI features. Confidence: 0.7
- Removing `panel/**` from `web_accessible_resources` is conditional: keep it if any proposed feature needs it. Confidence: 0.7
- Built-in AI (Prompt API) calls are panel-local by design: they run only in the DevTools panel or in a Worker the panel starts; the page, content scripts, and service worker never host `LanguageModel`, both because a page could read or forge the exchange and because Edge exposes no `LanguageModel` there without flags. Confidence: 0.9
- The MAIN-world script is limited to reading the page (`ng.ɵsetProfiler`, `ng.ɵgetSignalGraph`) and sending shaped facts to the panel; it never runs Prompt API, and the prompt half of the page bridge is removed. Confidence: 0.85
- Prompt text to small local models should be a short fact list with no tool calling, so Gemini Nano can answer. Confidence: 0.85
- A Worker must not call `LanguageDetector` or `Translator` itself (renderer crash); it forwards those calls to the panel. Confidence: 0.85
- Built-in AI availability/status in the panel reflects the panel's own `LanguageModel.availability()`, not proxied page state. Confidence: 0.85
- AI/model calls require an explicit user action (e.g. picking an item and clicking explain); no auto-trigger or auto-explain without an explicit pick. Confidence: 0.8
- Inspection/recording tooling must not mutate the inspected app: do not run Angular's `angular:di_graph` tool or call `getViewContainerRef()` on component hosts (which removes the template node from the signal graph). Confidence: 0.8
- Angular AI DevTools must not depend on dev-server instrumentation: it supports any served Angular application running in Development mode, whether served statically or via a dev server, and opt-in runtime instrumentation is allowed only via providers (e.g. `provideAiDevTools()`), never via dev-server instrumentation. Confidence: 0.95
- When showcasing browser AI APIs in Storybook/devtools stories, account for unsupported or unusable fallback states (e.g., Firefox lacking the Prompt API, Edge without the relevant feature flags) rather than assuming support. Confidence: 0.8
